Find the space your disk is actually wasting.

OmniClean is one 186 KB executable with no runtime dependencies. It scans every cache category Windows and your apps leave behind, walks entire volumes for oversized files, and finds byte-identical duplicates with SHA-256. Every deletion is previewed first, then written to an audit manifest.

Beyond cache cleaning

Four tools that find what a category list cannot

A fixed taxonomy only reaches the folders we know about. These tools go looking for the ones we do not.

01

Deep storage scan

Walks an entire volume rather than your user profile, because large media and archives usually live outside it. Reparse points are skipped, so a junction pointing back up the tree cannot turn the walk into an infinite loop. Results are ranked by file, folder and file type.

Minimum size filter from 50 MB to 5 GB

02

Duplicate finder

Two-phase detection. Files are grouped by exact byte size first, then size-matched candidates are hashed with a full-file SHA-256 stream. No prefix hashing, no false positives. Originals stay marked and only redundant copies are ever offered for removal.

Byte-level certainty, not a guess

03

Startup manager

Reads auto-launch entries from both HKCU and HKLM Run keys. Disabling an entry parks it under HKCU\Software\OmniClean\DisabledStartup instead of deleting it, so the launch command survives and can be restored at any time.

Machine-wide entries report when admin rights are needed

04

Memory trim

Flushes idle working sets through the Windows PSAPI subsystem to hand physical memory back to the system. Background applications keep running; nothing is terminated or restarted.

No resident daemon, no tray icon

Safety model

What OmniClean will never do

A storage cleaner is only useful if you can trust it. These boundaries are enforced in both engines and asserted by the test suite, not just documented.

  • Never deletes personal documents

    Documents, Desktop, Pictures, Music and OneDrive are untouched by general cleanups. Large files and duplicates are only removed after you review them individually.

  • Never touches logins, cookies or history

    Browser cleaning is restricted to Cache, Code Cache and GPUCache. Saved passwords, cookies, session tokens and bookmarks are never read or deleted.

  • Never sweeps the registry

    No speculative registry cleaning that can break COM interfaces or file associations. Registry access is limited to reading and toggling documented startup keys.

  • Never defragments SSDs

    Solid state drives take unnecessary flash cell wear from traditional defragmentation. OmniClean does not touch storage media layout.

  • Never runs in the background

    Zero tray icons, zero resident services, zero resource use when closed. Scheduled runs rely entirely on the built-in Windows Task Scheduler.

How a cleanup is gated

  1. 1

    Scan and measure

    Every target's real size is computed on disk. Nothing is estimated.

  2. 2

    Preview by default

    The API treats dryRun as true unless the caller explicitly asks otherwise. The UI ships with preview switched on.

  3. 3

    Confirm with impact summary

    A live run requires an explicit confirmation showing the selected targets and estimated reclaim.

  4. 4

    Write an audit manifest

    Every removed item, every failure and its reason, and a final summary are written to %APPDATA%\OmniClean\logs.

A protected-path guard exists in both engines: WinSxS, Installer, DriverStore, Package Cache, System32\config and Program Files can never be emptied, even if a taxonomy entry points at them.

Under the hood

Two editions, one engine definition

The native build is C# 5 and WPF on the .NET Framework that ships with Windows. The web edition is a local Node backend driving the same PowerShell engine. Both read the same taxonomy.

Build the native executable

No Visual Studio and no third-party SDKs. build.rsp holds the compiler flags so the script, CI and a manual build can never drift apart.

build.bat

Or directly with the .NET compiler:

$csc = "C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe"
& $csc "@build.rsp"

Run the web edition

Node.js 18 or newer. The server binds to loopback only, rejects foreign Host and Origin headers, and executes PowerShell through an argument array rather than a shell.

npm ci
npm start

Then run the suite:

npm test
